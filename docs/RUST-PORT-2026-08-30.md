## 1 · What was wrong, and it was not the code

`~/snitch` had been Python since its first commit on 2026-08-25. The audit that preceded this
never questioned it, and neither did the two work orders it was written against: both assumed
Python because the existing package was Python. That is how a standing rule gets quietly skipped.
It was raised by Ken, not by the audit, and that is the actual failure this document records.

Python was never forced here. The measurements below are the argument.

| | Python | Rust |
| --- | --- | --- |
| `snitch-mcp` resident, idle | **66.8 MB** | **2.4 MB** |
| What you install | 79 MB of site-packages plus a runtime | **4.3 MB**, four binaries |
| Direct dependencies | 2, plus an MCP SDK on 3.10+ only | **6** |
| Whole dependency tree | Pillow, mcp, and the mcp tree | **46 crates** |
| Async runtime | tokio, dragged in by the MCP SDK | **none** |
| Python floor question | a live constraint, MCP needs 3.10+ | **gone** |

Measured on this machine, both servers idle on stdio, same state.

## 2 · Parity, proved rather than asserted

The law is that old code is copied exactly, not reinterpreted. So the Python was not thrown away:
it is the specification, and the port is diffed against it.

Both implementations were run against the same fixtures in separate clean directories, and the
harness compares terminal output, exit status, the file listing and the bytes of every file
produced.

| | Result |
| --- | --- |
| `snitch`, 15 invocations including `--json`, `--platforms`, `--notes`, `--check`, missing files | **15 / 15 byte-identical**, exit codes included |
| `no-comment`, 8 invocations including `-o`, `--in-place`, `--force`, collisions | **8 / 8 byte-identical**, including the stripped output files themselves |
| `credit`, 18 invocations including licences, keywords, `--verify`, every validation refusal | **15 / 18 byte-identical** |

The three that differ print argparse's usage block above an error line that is itself byte
identical, on the same exit code. That is the price of the no-CLI-framework rule and it is the
whole of it. The JSON reports match down to key order, which matters because
`snitch --platforms --check` tells people to save a report, upload the file, save a second report
and diff the two.

The C2PA manifests match too. A file signed by the Rust validates under the Python and reports the
same issuer, the same assertions and the same `digitalSourceType`.

## 3 · The house style, and the two crates it refused

`~/.claude/skills/rust-for-this-machine` is the standard: no async, no web framework, no CLI
framework, and a dependency needs a reason you would defend out loud. Both refusals were measured
with `cargo tree` before deciding, and the numbers are in `Cargo.toml` so the next person does not
have to re-derive them.

**`c2pa`, the Rust library behind c2patool: 280 crates.** c2patool is that library already
compiled. It is a binary the user installs once, it is what the Python called, and shelling out to
it keeps the tree at 46. Six times the dependency tree to remove one subprocess is not a trade this
codebase makes.

**`rmcp`, the official Rust MCP SDK: 59 crates, and it brings tokio.** MCP over stdio is
newline-delimited JSON-RPC 2.0 read from one pipe and written to another. That is a blocking read
loop and about two hundred lines against `serde_json`, which was already a dependency. This is a
single-operator tool answering one request at a time over a pipe, which is exactly the case the
no-async rule exists for.

**ExifTool stays a subprocess.** Nothing in any language matches its tag database, and none of the
Rust EXIF crates write IPTC Core, XMP-plus and XMP-iptcCore the way a picture desk expects. The
Python shelled out to it and so does this. The cost is one process per call and a stated dependency.

**CRC-32 is hand-written**, twenty-five lines and one table, because a crate for it would save
nothing. So is the `which` lookup, and so is argument parsing.

The six that earned their place: `serde`, `serde_json`, `sha2`, `image` (jpeg and png features
only), `flate2` for the PNG text chunks, and `ab_glyph` to rasterise the stamp text.

`serde_json` carries the `preserve_order` feature, which costs three transitive crates and buys
stable key order in every report. That is not cosmetic, for the diffing reason above.

## 4 · Two bugs the port found, both real

Neither existed in the Python. Both are mine, both were caught by a test, and both now have one.

**The pixel proof was decoding by file extension.** `strip_atomic` writes to a sibling temporary
named `.tmp`, and `image::open` guesses the format from the extension, so the decode failed and
`pixels_identical` returned `None`. Every strip then refused itself with
`refusing to write output: pixel comparison unavailable`. That is the correct refusal for entirely
the wrong reason: the check was broken, not the surgery. It sniffs the bytes now.

**The MCP handshake answered with a version no client would take.** The official SDK's
`LATEST_PROTOCOL_VERSION` is `2026-07-28`, so that is what the server offered. But that version is
adopted **after** `initialize` through a separate mechanism; the handshake itself only settles one
of `2024-11-05`, `2025-03-26`, `2025-06-18`, `2025-11-25`. A conforming client abandoned the
session with *"Unsupported protocol version from the server"*. It negotiates from the handshake set
now, echoing the client's version when it can, and `tests/mcp.rs` holds it there.

The second one is the reason the rule about checking the live API rather than training data exists.
It was found by driving the Rust server with the official Python MCP client over a real pipe, which
is the only kind of test that could have found it.

## 5 · What shipped

```
snitch, no-comment, credit    three commands, because the name IS the interface
snitch-mcp                    a local stdio MCP server, five tools, no async
```

- **4,506 lines** of Rust, **1,643** more in tests, **68 tests**.
- `cargo clippy --all-targets -- -D warnings` clean. `cargo fmt --check` clean.
- CI on Linux, macOS and Windows, with ExifTool installed on all three and c2patool built on Linux
  so the C2PA tests are real rather than hand-written manifests. The retired Python still runs its
  own 101 tests, ruff and mypy, in the same workflow.
- A release workflow builds and attaches binaries for five targets, so a download link on the
  releases page is a real file rather than a promise. That closes audit finding P0-2.
- The README no longer instructs `pip install snitch-tools`, which returns HTTP 404. That closes
  P0-1.

### The four truth fixes from the audit, carried into the Rust

All still hold, all still tested.

- `snitch` reports PNG `tEXt`, `zTXt` and `iTXt`, names the generator, and says in as many words
  that a text chunk is plain text and proves nothing on its own.
- A tampered signature says **ALTERED AFTER SIGNING** rather than a bare `[Invalid]`.
- The five C2PA states are preserved, including `detected-unverified`, which is the one that stops
  "we could not check" collapsing into "there is nothing there".
- `snitch_clean_text` never touches ZWJ or ZWNJ. The test matrix covers emoji sequences, Persian,
  Kurdish, Devanagari and Bengali, and it is the reason that cannot regress.

The Pillow floor finding (P1-1) is gone rather than fixed: there is no Pillow.

## 6 · Still open

- **PyPI.** Nothing to publish now. `pip install snitch-tools` is gone from the README, and the
  install is a binary or `cargo install`. If a Python package is ever wanted again it would be a
  wrapper around the binary, and that is a separate decision.
- **crates.io.** Not published. `snitch-tools` is available as a crate name and the manifest is
  ready for it. Outward-facing and effectively irreversible, so it waits for a yes.
- **The web side.** `~/3d3d-site` is another agent's. Audit findings LIVE-1 (the Cloudflare beacon
  injection the CSP happens to block), LIVE-2 (the analytics pixel firing with GPC set), P1-2 (the
  web integrity claim being offline-verified rather than per-run) and the `/snitch` footer defect
  all belong there and are unchanged by this.
- **Platform round-trips.** Every row of the survival table is still marked unverified inference,
  honestly, dated `2026-08-25`. It needs real accounts and real uploads.
